# Remote Codex

Отдельный мобильный интерфейс к локальному Codex `app-server`. Сервис работает
только с корнем этого репозитория и запускает Codex в sandbox `workspace-write`
в режиме `Approve for me`: политика `on-request` создаёт запросы на проверку,
а `auto_review` автоматически рассматривает их и передаёт пользователю только те,
которые требуют его решения.

Кнопка `☰` открывает последние сессии текущего проекта. Активная сессия выделена;
нажатие на другую сессию загружает её историю и продолжает диалог в ней.
При восстановлении загружаются последние 50 ходов с полным составом сообщений и
действий; история берётся через пагинированный `thread/turns/list`, а не из
ограниченного представления, возвращаемого `thread/resume`.

На Windows сервис автоматически использует наиболее свежий `codex.exe` из
расширения Codex для VS Code, чтобы формат сессий совпадал с IDE. При необходимости
путь можно задать вручную через `REMOTE_CODEX_EXECUTABLE` в `.env`.

Команда `npm run remote-codex` запускает безопасный supervisor. Изменения файлов
из `public` доступны сразу после обновления страницы и не перезапускают app-server.
При изменении `server.ts` supervisor перезапускает процесс сразу, если он свободен,
либо откладывает рестарт до `turn/completed`, чтобы не оборвать результат инструмента.

Codex разрешает только один процесс записи в сессию. Пока диалог открыт активным
writer в IDE, Remote Codex покажет его в списке, но продолжить его можно только после
освобождения сессии в IDE. В этом случае новый запрос с телефона создаст отдельный
диалог. Watch-перезапуск корректно завершает дочерний app-server, чтобы не оставлять
собственные блокировки.

Сообщения поддерживают fenced-блоки Markdown (` ```язык `) и inline-код. Блоки
оформляются отдельно от текста и содержат кнопку копирования.

Действия агента группируются в свёрнутую карточку `Edited n files, ran n commands`.
Перед финальным ответом показываются время работы (`Worked for 36s`) и разделитель,
как в интерфейсе расширения Codex для VS Code.
Промежуточные комментарии и карточки действий сворачиваются в общий раздел
`n previous messages`; отдельные серии действий внутри него остаются самостоятельными.
У каждого сообщения пользователя и агента есть время отправки, которое появляется
в правом нижнем углу при наведении (или при нажатии на сенсорном экране).

## Запуск

Убедитесь, что Codex CLI установлен и авторизован на компьютере, затем из корня
репозитория выполните:

```powershell
npm run remote-codex
```

При первом запуске в терминале появится токен. Он также сохраняется в игнорируемом
файле `.cache/remote-codex-token`. Откройте на телефоне:

```text
http://<IPv4-компьютера>:3210
```

Например:

```text
http://192.168.1.38:3210
```

Введите токен один раз. Браузер получит `HttpOnly`, `SameSite=Strict` cookie на
30 дней, и авторизация сохранится после перезапуска Remote Codex. Cookie содержит
HMAC-производную токена, а не сам токен; смена `REMOTE_CODEX_TOKEN` автоматически
завершает ранее выданную браузерную сессию. Если Windows Firewall спросит
разрешение, разрешайте только частную сеть.

## Собственный токен

Рекомендуется указать длинный случайный токен в корневом `.env`:

```dotenv
REMOTE_CODEX_TOKEN=замените-на-длинную-случайную-строку
REMOTE_CODEX_HOST=0.0.0.0
REMOTE_CODEX_PORT=3210
```

После изменения требуется перезапуск сервиса.

## Tailscale

Tailscale пока не установлен на этом компьютере. После его установки безопаснее
оставить gateway на loopback:

```dotenv
REMOTE_CODEX_HOST=127.0.0.1
```

и опубликовать `http://127.0.0.1:3210` через Tailscale Serve. Не пробрасывайте
порт `3210` напрямую в интернет и не используйте `danger-full-access`.

## Ограничения MVP

- один workspace и одна активная задача;
- поддерживаются approvals команд и изменения файлов;
- запросы дополнительных системных разрешений и интерактивные формы инструментов
  намеренно отклоняются как неподдерживаемые;
- протокол `app-server` экспериментальный, поэтому адаптер может потребовать
  обновления после смены версии Codex CLI.
